# ADR-003：同仓独立管理后台

- 状态：已采纳
- 日期：2026-07-29
- 决策人：产品确认
- 关联：ADR-002、PRD v0.8.0 D34–D42

## 背景

现有 `web/` 同时承载员工系统对话与部分业务控制台。新增管理后台需要面向平台管理员和超级管理员提供高密度配置治理、审计与运维能力，其导航结构、权限边界、发布节奏和视觉布局均与员工端不同。

继续将管理能力堆入 `web/` 会扩大共享布局与样式耦合，增加员工端回归范围；拆为独立仓库又会造成接口契约、认证与 AI 开发上下文漂移。

## 决策

保持 monorepo，在仓库中采用三个独立应用边界：

- 员工端：`web/`，Next.js，默认端口 3000；
- 管理端：`admin-web/`，Next.js，默认端口 3001；
- 后端：`src/app/`，FastAPI，默认端口 8000。

`admin-web/` 独立安装、构建、部署与回滚，通过同源 `/api/*` 代理复用 FastAPI 账号、Session 和业务接口。首期不创建跨应用共享组件包，避免为少量复用提前抽象；稳定的类型或设计令牌出现重复需求后再评估 `packages/`。

## 权限与安全

1. 管理端仅允许 `platform_admin`、`super_admin`；
2. 管理接口必须强制校验已认证 Session，未登录不得默认管理员；
3. 测试角色请求头仅在测试环境显式启用；
4. 员工端不展示管理菜单；管理端不承载员工对话主入口；
5. 两个前端均不得持有数据库、Redis 或模型服务密钥。

## 后果

### 正向

- 员工端与管理端发布风险、导航和样式隔离；
- 保持单仓接口契约和开发上下文；
- 可按访问量分别扩缩容与回滚；
- 后续管理功能扩展不挤压员工对话体验。

### 代价

- 两个 Next.js 应用分别维护依赖与构建缓存；
- 登录页、请求封装和少量设计令牌存在有限重复；
- 部署、反向代理和本地启动脚本需要增加管理端端口。

## 与 ADR-002 的关系

本决策不推翻 ADR-002 的“前后端同仓”原则，只修订其“前端仅位于 `web/`”的目录表述。自 2026-07-29 起，前端应用位置以本 ADR 和 PRD v0.8.0 为准。
