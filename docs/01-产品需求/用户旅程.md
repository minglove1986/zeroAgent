## 旅程 1：员工查年假制度（RAG 问答 + 可能提问卡）

### 参与者
员工小王（普通员工）

### 前置条件
- 业务专家已上传《员工手册》到 HR 知识库并发布（命中测试通过）
- 小王对 HR KB 有并集权限（部门或角色命中）
- 小王已有 Web 账号并可登录

### 流程

```
1. 小王登录 Web → 打开「系统对话」："年假怎么请？"
2. 若路由低置信 → 澄清卡片选 Agent
3. 若技能调用 ask_user（如请假类型）→ 提问卡片 → 小王 card-action
4. HR Agent → rag_search → 召回条款
5. LLM 生成答案 + 强制文档 citation
6. 流式展示；来源 + 👍/👎
```

### 异常路径
- top-k 相似度均 < 0.55 → 「未找到相关信息」+ 引导追问（不编造）
- RAG 无 citation → 系统拒绝展示
- 必填卡未答又直接 send → 42213
- 账号停用 → 无法登录

## 旅程 2：HR 配置新员工入职流程（工作流 + 技能触发）

### 参与者
HR 张姐（业务专家）

### 前置条件
- 张姐可创建工作流；平台已有「开账号」等 HTTP 工具挂在技能上

### 流程

```
1. 张姐在 Web 打开工作流编辑器
2. 基于模板「HR-新员工入职」拖拽配置（HTTP / 通知 / 人工节点）
3. 保存；定时或手动触发时系统写入实例 DAG 快照
4. 另：创建「请假/入职」工作流技能，绑定 workflow_call；需要时挂 ask_user
5. 将技能绑到 HR Agent（Agent 不直绑工作流）
6. 员工在系统对话触发技能 → 技能调用工作流 → 跑快照实例
7. 人工节点 → Web 待办确认 → 续跑；通知节点 → 站内通知
```

### 异常路径
- 某 HTTP 节点失败 → 按节点重试后立即失败 → 站内通知/Webhook
- 编辑工作流定义不影响已在跑的实例（仍跑触发时快照）

## 旅程 3：研发查代码指标（技能 → 工具 FC）

### 参与者
研发小李（普通员工）

### 前置条件
- CodeHelper Agent 已绑「代码指标」技能；技能绑 GitLab HTTP 工具
- 小李对工具有权限

### 流程

```
1. 小李在系统对话选择 CodeHelper：「A 模块单元测试覆盖率」
2. Agent 层 FC：选择「代码指标」技能（不可直调 GitLab 工具）
3. 技能层 FC：调用 GitLab 工具（必要时先 ask_user 确认仓库）
4. 返回结果；追问时继续在技能/工具层处理
```

### 异常路径
- 工具 401 → 返回错误提示
- 高风险工具 → Web `/approvals`（默认本人）

## 旅程 4：业务专家上传部门规章（知识库维护）

### 参与者
财务王姐（业务专家）

### 前置条件
- 超管已创建「财务部知识库」并授权王姐 write

### 流程

```
1. 王姐登录 Web 控制台 → 财务部知识库
2. 上传报销制度.pdf 等，并填写问答对（默认 ≥5 条）
3. 系统解析 / Embedding / 自动命中测试
4. 召回率 ≥80% → 王姐点击发布；否则禁止发布
```

## 旅程 5：销售查客户信息（KG + 内部 Agent 互调）

### 参与者
销售小赵（普通员工）

### 流程

```
1. 小赵在系统对话问：「A 公司的决策人是谁？」
2. 路由到 Sales Agent → rag_search / KG
3. 追问合同细节时：Sales Agent call_agent(合同 Agent)（深度 1）
4. 合同 Agent 不可再 call_agent；结果汇总回主对话；计费归小赵
```

### 异常路径
- 目标不在白名单 / 将成环 → 拒绝互调并提示

## 跨旅程设计原则

1. **Web 对话优先**：系统对话含交互卡片 / `ask_user` 提问
2. **两层 FC**：Agent 选技能/RAG/内部 Agent；原子工具与 `ask_user` 只在技能内
3. **RAG 强制引用**：有检索则必须 citation
4. **反馈闭环**：👍/👎
5. **权限并集**：本人/任一部门/任一角色命中即可访问 KB
6. **IM 延后**：OpenIM / 钉钉等不进入本阶段旅程
