## 一、产品定位

| 项 | 描述 |
|---|---|
| **产品名** | zeroAgent（智囊） |
| **定位** | 企业内部统一 AI 助理入口，**以 Web 对话为主** |
| **目标** | 1 个入口解决 80% 内部知识获取与流程自动化需求 |
| **形态** | **同仓多前端应用**：`web/`（员工端系统对话与业务控制台）+ `admin-web/`（独立管理后台）+ `src/app/`（FastAPI）+ OpenAPI；**本阶段不接入 OpenIM / 企业 IM** |
| **用户规模** | 中型，200-2000 用户 |
| **MVP 时间** | 8 周 |
| **租户模式** | 单租户（暂不支持多租户隔离） |
| **对话入口** | 员工端登录后进入 **系统对话界面**（流式回复 + 交互卡片）；IM 通道整体 **延后可选** |
| **管理入口** | 管理员登录独立 `admin-web/` 后进入 `/overview`；非管理员禁止访问 |
| **工程结构** | **Monorepo**（D34–D35）：员工端 `web/`、管理端 `admin-web/`、后端 `src/app/`；均在同一仓库，不拆独立仓库 |

## 二、用户角色与权限模型

### 2.1 角色定义

| 角色 | 典型用户 | 核心诉求 |
|---|---|---|
| **普通员工** | 全员 | 问规章、查文档、提流程 |
| **业务专家** | HR/财务/IT/法务 | 维护**授权范围内**知识库文档、创建工作流、领域技能 |
| **Agent 开发者** | IT/业务骨干 | 编排工作流、配置 Agent / 技能 |
| **部门管理员** | 部门 IT/BP | 本部门用量/告警、用户只读、对话脱敏只读（不可启停用户/改角色/系统配置） |
| **平台管理员** | IT 管理员 | 用户/权限/审计/计费、创建 Agent、维护记忆抽取白名单与 L2 关键词 |
| **超级管理员** | CTO/IT 总监 | 全部权限 + 系统配置 |

### 2.2 角色特点

- **角色可配置**：管理员可创建/编辑角色，灵活分配菜单权限和数据权限
- **多部门归属**：一个用户可属于多个部门（支持兼职、跨部门项目）
- **主部门优先**：成本分摊以用户主部门为准
- **不预设 Agent 数量**：管理员按需创建 Agent

| 邮箱 | ✅ | 通知用（告警/邮件可选） |
| 职位 | ✅ | 显示用 |
| 入职日期 | ✅ | 统计用 |

### 3.2 登录策略

| 维度 | 决策 |
|---|---|
| 登录入口 | 员工端 `web/` 与管理端 `admin-web/` 各自提供登录页，复用同一账号体系与后端 Session；管理端额外校验管理员角色 |
| 会话有效期 | **8 小时** |
| 多端登录 | **不限制**（同时多端可登录） |
| 密码策略 | **极简**：6 位以上，无复杂度要求 |
| 登录安全 | **基础**：无锁定、无过期、无 MFA |
| 用户维护 | **手动**：管理员在 Web 后台增删改 |
| 组织结构 | **多部门**：一个用户可属于多个部门 |
| 角色模型 | **可配置**：管理员可创建/编辑角色 |
| 对话身份 | **登录 Session = 对话身份**；无需 IM 映射 / 自助绑工号 |

### 3.3 系统对话界面（Web UI）

#### 3.3.1 架构（现行）

```
员工登录 Web 控制台
        ↓
  打开「系统对话」页（可指定 Agent / 自动路由）
        ↓
  SSE/流式回复 ← Agent（技能两层 FC + KB/KG + 内部 call_agent）
        ↓
  附件：对话页或控制台上传 → 写 OSS → Celery 解析入库
```

#### 3.3.2 Web 对话决策

| 维度 | 决策 |
|---|---|
| 主入口 | **系统对话页**（P0） |
| 消息格式 | 文本 + Markdown + **交互卡片**（D31）；附件（文件/图片）上传 |
| 流式 | **SSE**（或等价流式）展示首字与增量；卡片可在流式结束后或中途以独立事件下发 |
| 路由策略 | **可指定 Agent** + 关键词/LLM 自动路由；低置信时 **Web 澄清卡片**（选 Agent） |
| **Agent 提问** | Agent 需要用户补充信息时，下发 **提问卡片**（单选/多选/填空/确认），用户作答后继续对话（D32） |
| 交互按钮 | 卡片按钮配置化（发消息 / 提交选项 / 打开链接 / 触发审批待办）；高风险仍走 `/approvals` |
| 文件入库 | **Web 上传 → 服务端写 OSS → Celery**（D25） |
| 测试中 Agent | 控制台/API/系统对话均可聊（D10） |

#### 3.3.2b 交互卡片能力（P0）

| 卡片类型 | 用途 | 用户动作 |
|---|---|---|
| `markdown` | 普通富文本回答（可含 citation） | 👍/👎/重试 |
| `route_clarify` | 路由低置信：请用户选 Agent | 点选一个 Agent |
| `ask_choice` | Agent 提问：单选/多选 | 选选项后提交 |
| `ask_form` | Agent 提问：需填写字段（短文本/数字等） | 填表提交 |
| `ask_confirm` | Agent / 技能请求确认（非高风险） | 确认 / 取消 |
| `approval` | 高风险工具 / 人工节点 | 跳转或内嵌待办，走 `/approvals` |
| `actions` | 通用操作条 | 配置化按钮（打开链接、继续追问话术等） |

**规则**：

1. 卡片由服务端以结构化 JSON 下发（SSE 事件 `card`），前端按 `type` 渲染，**禁止**仅靠 Markdown 伪按钮冒充交互。  
2. 用户提交卡片结果：`POST /messages/card-action`（或等价），携带 `card_id` + `payload`，服务端续跑同一会话。  
3. Agent「提问」属对话内交互，**不**等同高风险审批；高风险仍必须 `approval_tasks`。  
4. 同一消息可含：流式文本 + 0..N 张卡片；未完成必填提问卡时，可阻塞后续自动续跑直至用户作答或超时（默认 30 分钟，与审批超时对齐可配）。  
5. **触发方式（D33）**：技能层可挂内置工具 **`ask_user`**；LLM 在技能 FC 中调用后，运行时转为对应提问卡（`ask_choice`/`ask_form`/`ask_confirm`）。路由澄清由路由模块直接发 `route_clarify` 卡，不经 `ask_user`。Agent 层**不可**直接暴露 `ask_user`（保持两层 FC）。  

#### 3.3.3 典型使用流程

1. 员工用账号密码登录 Web 控制台  
2. 进入「系统对话」，可选指定 Agent 或使用智能路由  
3. 发送问题；需要时上传附件  
4. Agent 调用 LLM + 技能/工具 + 知识库；若信息不足 → 下发提问卡片  
5. 用户在卡片上选择/填写 → 继续生成；流式展示 + citation；高风险弹出审批  

#### 3.3.4 用户停用数据处理

| 维度 | 决策 |
|---|---|
| 数据保留 | **全部保留**：账号停用但数据保留，管理员可查 |
| 对话历史 | 保留 90 天（按系统留存策略） |
| 配额/费用 | 保留记录，成本归零 |

#### 3.3.5 IM 通道（延后 · 本阶段不做）

| 项 | 现行 |
|---|---|
| OpenIM | **不接入**（不实现同步、机器人、file-callback） |
| 飞书/钉钉/企微 | **产品级接入不做**（Webhook 告警除外，见 D22） |
| 卡片能力 | **在 Web 系统对话实现**（不依赖 IM 卡片协议） |
| 未来 | 可作为可插拔「通道适配器」；业务卡片模型可复用 |

## 四、核心场景与功能清单

### 场景 1：智能问答（基础能力）

**用户故事**：
> 作为员工，我在 Web「系统对话」里问"年假怎么请"，助理能直接给我答案并附上原文链接。

| 编号 | 功能 | 优先级 |
|---|---|---|
| F1.1 | 多轮对话（带上下文） | P0 |
| F1.2 | RAG 知识库问答 + **强制引用溯源** | P0 |
| F1.3 | 流式输出（SSE） | P0 |
| F1.4 | Markdown / **交互卡片**渲染（含 Agent 提问） | P0 |
| F1.4b | 卡片动作回传（选项/表单/确认）并续跑对话 | P0 |
| F1.5 | 多模态输入（图片、PDF、语音） | P1 |
| F1.6 | 多语种（中英） | P1 |
| F1.7 | 反馈机制（👍/👎 + 文字反馈） | P0 |

**关键约束**：

| 维度 | 决策 |
|---|---|
| 引用溯源 | **RAG 强制**：本轮使用了检索结果则必须含文档 citation，否则拒绝展示；纯技能/工具/互调不强制（v0.7 裁定 D14） |
| 输出审核 | 关键词过滤（敏感词由管理员维护，5000 词，中文） |
| 流式输出 | **默认流式**（SSE，首字延迟 < 1.5s） |
| 无答案 | top-k 相似度均低于系统阈值（默认 **0.55**）时直接告知+引导追问 |

### 场景 2：知识库管理

**用户故事**：
> 作为超管，我把部门规章上传到知识库，让员工随时能问。

| 编号 | 功能 | 优先级 |
|---|---|---|
| F2.1 | 文档上传（PDF/Word/Excel/PPT/TXT/Markdown + 网页 URL） | P0 |
| F2.2 | 知识库分类（按部门划分，< 10 个） | P0 |
| F2.3 | 父子分块（小块 200 字检索，大块 1000 字喂 LLM） | P0 |
| F2.4 | **自动命中测试**：上传后自动验证召回率，不达标不允许发布 | P0 |
| F2.5 | 文档版本管理（新版本保留历史） | P0 |
| F2.6 | **软删 + 审计 + 恢复**：30 天内可恢复 | P0 |
| F2.7 | 网页 URL 抓取 | P0 |
| F2.8 | 多 KB 权限（用户/部门/角色自定义） | P0 |

**关键约束**：

| 维度 | 决策 |
|---|---|
| 知识库所有权 | 按部门划分 |
| 创建权限 | 仅超管 |
| KB 文档维护 | **超管建库；业务专家可对授权范围内 KB 上传/编辑**（v0.7 裁定 D4） |
| KB 管理员 | 超管负责建库与全局策略；专家负责授权范围内内容 |
| 文档上传方式 | 手动上传（Web 表单/拖拽/URL） |
| 文件格式 | 基础（PDF/Word/Excel/PPT/TXT/Markdown）+ 网页 |
| 文件大小 | 单文件 ≤ 50MB |
| 文档更新 | 新版本（保留历史） |
| KB 权限 | 自定义（用户/部门/角色）；合并规则为**并集**（v0.7 裁定 D13） |
| 检索方式 | **可配置**：Agent 可选三路（向量+BM25+Rerank）或四路（+KG） |
| 三路路径 | **Milvus 稠密（BGE-M3）+ Milvus 稀疏/BM25（Hybrid）+ Rerank（BGE-Rerank）** |
| 四路路径 | 三路 + **KG 查询（Neo4j NL→Cypher/RAG 降级）** |
| 并行执行 | 三路/四路**并行执行**，总耗时 < 500ms |
| 合并策略 | **RRF（倒数排名融合）**：按各路径排名倒数加权合并去重 |
| Top-K | **固定 5**（不开放调参） |
| KG 失败处理 | 超时 2s → **自动跳过**，降级到三路 |
| Rerank 模型 | **BGE-Rerank 本地 CPU**（与 Embedding 同机部署） |
| 检索框架 | **LlamaIndex**（作为数据/检索层，Agent 不可见） |
| 文档解析 | **LlamaIndex 编排 + MinerU（PDF 默认本地）+ Unstructured/Readers；LlamaParse 可选外呼（默认关）** |
| 分块策略 | **SmartChunker**（按文件类型选分块器） |

### 场景 4.1：Agent 技能（Skill）系统

### 场景 4.2：Agent 编排框架（LangGraph + LangChain）

**核心选型**：

| 维度 | 决策 |
|---|---|
| Agent 编排框架 | **LangGraph + LangChain** |
| 编排模式 | **条件分支** |

**架构设计**：

```
用户问题
   ↓
┌──────────────────────────────────────┐
│  Planner（Plan-and-Execute 大循环）   │
│    - 分析问题，制定计划                │
│    - 拆解为多个子任务                  │
└──────────────┬───────────────────────┘
               ↓
   ┌───────────┴───────────┐
   ↓                       ↓
┌─────────────────┐ ┌─────────────────┐
│ Executor 1      │ │ Executor 2      │
│ (ReAct 小循环)  │ │ (ReAct 小循环)  │
│ Thought →       │ │ Thought →       │
│ Action →        │ │ Action →        │
│ Observation →   │ │ Observation →   │
│ (loop until OK) │ │ (loop until OK) │
└─────────────────┘ └─────────────────┘
   ↓                       ↓
   └───────────┬───────────┘
               ↓
┌──────────────────────────────────────┐

│    - 汇总所有子任务结果                │
```

**LangGraph 图构建**：

```python
    return create_plan_execute_graph(llm, skills + [rag_search, call_agent])
```

**核心约束（陛下四大原则）**：

### 原则 1：强制分层隔离

| 层级 | 可调用的工具 |
|---|---|
| **Agent（LangGraph）** | 仅技能 + RAG + **内部 `call_agent`**（**不直接调用原子工具**） |
| **技能** | 原子工具（含高风险校验）+ 可选 `workflow_call` |
| **工具** | 外部 API / DB / 文件（最底层） |

**禁止**：
- ❌ Agent 直接调用数据库工具
- ❌ Agent 直接调用 HTTP 工具
- ❌ Agent 直接调用文件工具
- ❌ 高风险工具暴露给 Agent
- ❌ 调用**外部** Agent / 外部 A2A（v0.7 裁定 D1）

**允许**：
- ✅ Agent 调用 `execute_skill`（或各技能 function）
- ✅ Agent 调用 `rag_search`
- ✅ Agent 调用 `call_agent`（白名单、深度≤2、禁环）
- ✅ 技能内部调用工具（含校验）
- ✅ 技能 `workflow_call` 触发工作流

**实现**：

```python
# Agent 只对接 3 类工具（v0.7：内部互调替代外部 A2A）
agent_tools = [
    execute_skill,        # 业务技能（或展开为各技能 function）
    rag_search,           # 知识库检索
    call_agent,           # 内部 Agent 互调（白名单）
]

# 技能内部封装工具调用
class SkillExecutor:
    async def execute(self, skill_id, **kwargs):
        skill = get_skill(skill_id)
        
        # 高风险校验（默认本人确认，可配审批人；超时 30 分钟）
        if skill.risk_level == "high":
            await self.require_approval(skill, kwargs)
        
        # 调用工具（含业务校验）
        result = await self.call_tools(skill.tools, kwargs)
        if not self.validate(skill, result):
            raise ValidationError("...")
        
        return result
```

### 原则 4：按领域治理

**工具按技术领域分类**：

| 技术领域 | 例子 | 标识前缀 |
|---|---|---|
| **database** | query_db, update_db, delete_record | `tool_db_*` |
| **http_api** | call_jira, call_crm, send_email | `tool_http_*` |
| **im** | send_im, send_card | `tool_im_*` |
| **file** | read_file, write_file | `tool_file_*` |
| **search** | web_search | `tool_search_*` |

**技能按业务场景分类**：

| 业务场景 | 例子 | 标识前缀 |
|---|---|---|
| **hr** | handle_complaint, leave_request | `skill_hr_*` |
| **finance** | reimbursement, expense_approval | `skill_fin_*` |
| **ops** | order_processing, customer_management | `skill_ops_*` |
| **rd** | code_review, bug_handling | `skill_rd_*` |

**禁止跨域**：工具按技术归类，技能按业务归类，**不混淆**。

### 风险等级与校验

| 风险等级 | 例子 | 是否封装在技能 | 校验 |
|---|---|---|---|
| **高风险** | 删除数据、发邮件、转账 | ✅ 必须 | **二次确认**（默认触发用户本人；可配审批人）+ 审计；超时 30 分钟取消（v0.7 裁定 D9） |
| **中风险** | 创建记录、更新非关键 | ✅ 必须 | 业务校验 |
| **低风险** | 只读、查询、计算 | ✅ 仍须经技能暴露给 Agent | 无额外确认 |

> 说明：低风险也**不得**由 Agent 层直接 FC；仅表示技能内调用时无需二次确认。

**高风险工具强制校验**：

```python
async def execute_high_risk_tool(tool_id, **kwargs):
    # 1. 仅允许从技能调用
    if not is_called_from_skill():
        raise PermissionError("高风险工具只能从技能调用")
    
    # 2. 参数校验
    validated = validate_params(tool_id, kwargs)
    
    # 3. 用户权限
    if not has_permission(user, tool_id):
        raise PermissionError("用户无权限")
    
    # 4. 审计日志
    await audit_log(user, tool_id, kwargs)
    
    # 5. 执行
    return await tool.execute(validated)
```

**工具注册（动态 + 强制分层）**：

| 类型 | 来源 | Agent 可见 |
|---|---|---|
| 技能 | `skill_ids` 从 agent.skill_ids 读 | ✅ |
| RAG | 内置（`rag_search`） | ✅ |
| 内部互调 | 内置（`call_agent`）+ Agent 白名单 | ✅ |
| 工具 | **技能内部封装，Agent 不可见** | ❌ |
| 工作流 | 通过技能 `workflow_call` 间接调用 | ❌ |

**内部 Agent 互调（替代外部 A2A，v0.7 裁定 D1/D17）**：

```
主 Agent（深度 0）
   └─ call_agent(子 Agent)（深度 1，须在白名单）
         └─ 子 Agent 不可再 call_agent（深度上限 2）
禁环：A→B→A 直接拒绝
权限：子 Agent 仍校验同一用户 + KB 并集；计费归主对话用户
```

| 维度 | 决策 |
|---|---|
| 外部 A2A Server/Client | **不做**（整系统目标架构亦不做外部 Agent） |
| 内部互调 | `call_agent(agent_id, query)` |
| 深度 | 默认 2 |
| 边 | 仅配置白名单 |
| 环路 | 检测并拒绝 |

**关键决策**：

| 维度 | 决策 |
|---|---|
| Agent 互相调用 | **仅内部** `call_agent`（白名单、深度≤2、禁环） |
| Agent 调工作流 | **通过技能**（不直调） |
| LangGraph 与工作流 | **并存**（各司其职） |
| RAG 集成 | **作为 LangGraph 工具**（`rag_search`） |
| 技能集成 | **作为 LangGraph 工具**（`execute_skill` / 技能 function） |
| 工具集成 | **不直接暴露给 Agent**，封装在技能内部（含高风险校验） |
| 工具注册 | **动态从数据库读 + Redis 缓存** |
| 图存储 | **动态构建**（按 Agent 配置） |
| 强制分层隔离 | **Agent 只对接技能+RAG+内部 call_agent**，禁止直接调用原子工具 |
| 描述边界 | **技能=业务目标，工具=执行动作** |
| 优先技能原则 | **Agent 系统 Prompt 强制约束** |
| 按领域治理 | **工具按技术领域，技能按业务场景** |
| 风险等级 | **高/中/低三级，高风险必须封装在技能内+二次确认（D9）** |

#### 5.12.3 分块策略（SmartChunker）

```python
class SmartChunker:
    def chunk(self, file_path: str):
        file_type = detect_type(file_path)
        
        if file_type == "pdf":
            # PDF：SemanticSplitter 找语义边界
            return self.semantic_chunk(file_path)
        
        elif file_type in ["md", "markdown"]:
            # Markdown：MarkdownNodeParser 保留结构
            return self.markdown_chunk(file_path)
        
        elif file_type in ["py", "js", "java"]:
            # 代码：CodeSplitter 基于 AST
            return self.code_chunk(file_path, file_type)
        
        elif file_type in ["xlsx", "xls"]:
            # Excel：行级 + 列级
            return self.excel_chunk(file_path)
        
        else:
            # 其他：HierarchicalNodeParser 父子分块（200/1000）
            return self.hierarchical_chunk(file_path, sizes=[200, 1000])
```

**分块器选择矩阵**：

| 文件类型 | 分块器 | 理由 |
|---|---|---|
| PDF | **SemanticSplitter** | 复杂布局需语义感知 |
| Markdown | **MarkdownNodeParser** | 保留标题/段落结构 |
| 代码（py/js/java） | **CodeSplitter** | AST 感知，语义完整 |
| Excel | **行级分块** | 表格结构 |
| Word/PPT/TXT | **HierarchicalNodeParser** | 与 PRD 一致（200/1000） |

### 12.1.7 L2 关键词规则管理

| 能力 | 要求 |
|---|---|
| 列表 | 分类统计、关键词搜索、分类/匹配方式/状态/来源筛选、服务端分页 |
| 字段 | 短语、分类、匹配方式、状态、优先级、来源、更新时间、操作 |
| 固定分类 | `explicit_kb`、`leave`、`meta_reply`、`doc_dump`、`doc_summarize`、`doc_critique`、`person_search_verb` |
| 匹配方式 | 仅 `contains` / `equals` / `prefix`；禁止自定义正则 |
| 唯一性 | 短语去除首尾空白；同一分类内不可重复 |
| 系统种子 | 可编辑、停用、恢复默认；不可删除 |
| 自定义项 | 可新增、编辑、启停、软删 |
| 生效 | 保存成功立即刷新 Redis 运行目录，无需重启或发布 |

**服务端真实试跑**：

- 输入一条测试语句，可选择当前已生效目录，或附带编辑中的未保存候选规则；
- 后端执行与生产一致的 L2 规则，返回漏斗层级、意图、置信度、原因、命中分类、短语、匹配方式、优先级；
- L2 未命中时只提示“将继续进入 L3”，不得伪造 L3 结论；
- 试跑不得创建对话、消息、记忆、审批或业务任务，仅写轻量管理审计。

### 12.1.8 即时生效、一致性与配置审计

配置保存顺序固定为：

```text
鉴权与参数校验
  → 校验配置修订号
  → 同一 MySQL 事务写配置与审计
  → 提交 MySQL
  → 刷新对应 Redis 目录并递增版本
  → 返回缓存同步状态与请求标识
```

| 场景 | 产品行为 |
|---|---|
| 数据库与缓存均成功 | 提示保存并立即生效，局部刷新列表 |
| 数据库成功、缓存失败 | 标记“部分成功”；页面顶部常驻警告并提供立即重试缓存同步 |
| 数据库失败 | 不改变运行配置，保留表单输入并允许重试 |
| 多人同时编辑 | 使用修订号检测；冲突返回 409，要求重新加载比较，禁止静默覆盖 |

本期审计至少记录：操作时间、操作人、角色、动作、资源、变更前后摘要、成功/部分成功/失败、请求标识。审计记录不可在管理后台修改或删除，不得写入 Session、密码、密钥或完整请求头。

完整交互、接口增量、数据模型与验收标准以 `docs/superpowers/specs/2026-07-29-admin-console-design.md` 为本版本补充设计依据。

## 十三、闭环流程（v0.5 新增）

### 13.1 Web 用户身份与对话准入

| 维度 | 决策 |

| 识别策略 | **登录 Session**（v0.7.2 修订 D8） |

### 13.2 知识库文档状态机

| 维度 | 决策 |
|---|---|
| 状态 | **草稿 → 发布**（两态） |
| 流程 | 1. 文档上传（须附带问答对，默认 ≥5 条）→「草稿」→ 2. 自动命中测试（top-5 命中期望段落比例）→ 3. 通过（≥80%）→ 有权限者可点「发布」；未通过 → 禁止发布 |
| 强制点 | 召回率 < 80% 或问答对不足 → 禁止发布 |

### 13.3 用户提问「无答案」兜底

| 维度 | 决策 |
|---|---|
| 兜底策略 | **直接告知 + 引导追问** |
| 触发条件 | RAG 检索 top-k 相似度均低于系统阈值（默认 **0.55**，可配） |
| 回复模板 | "抱歉，未找到与您问题相关的信息。您可以：1) 换个关键词试试；2) 描述更具体一点；3) 联系 XX 部门人工咨询" |
| 防幻觉 | 强制 LLM 不得编造信息，仅基于检索结果回答；RAG 路径无 citation 则拒展 |

### 13.4 KB 权限合并规则

| 维度 | 决策 |
|---|---|
| 合并方式 | **并集**（v0.7 裁定 D13） |
| 规则 | 用户本人 / **任一**所属部门 / **任一**角色对 KB 有授权，即有权 |
| 无权限处理 | 无权 KB 不参与检索（结果为空） |
| 示例 | 用户属于部门 A 和 B，KB-X 只授权给 A：并集命中 A → **有权** |

### 13.5 用户离职/转岗数据处理

## 十五、用户记忆系统（v0.6.1 新增）

### 15.1 记忆类型与范围

| 维度 | 决策 |
|---|---|
| 是否需要跨会话记忆 | **需要**（完整实现） |
| 记忆内容范围 | **完整**（偏好 + 事实 + 历史总结） |
| 偏好类型 | 简洁度、格式（Markdown/纯文本）、语言（中文/英文） |
| 事实类型 | 姓名、部门、岗位、入职时间、联系方式等 |
| 历史摘要类型 | 对话要点、进行中任务、常见问题 |

### 15.2 记忆抽取方式

| 维度 | 决策 |
|---|---|
| 抽取策略 | **手动 + 自动结合** |
| 自动抽取 | LLM 只能从管理员启用的记忆字段白名单中填值；禁止生成白名单外 `memory_key` |
| 管理员治理 | 独立管理后台维护白名单目录；MySQL 为真相源，写后刷新 Redis；停用后停止抽取与注入 |
| 手动管理 | 用户在“记忆管理”页面查看/编辑/删除自己的记忆；管理员停用字段不删除历史记录 |
| 默认行为 | 白名单内自动抽取 + 用户可手动修正；白名单外结果直接丢弃 |

### 15.3 存储架构

| 维度 | 决策 |
|---|---|
| 短期记忆 | **Redis 缓存**（当前会话上下文，TTL 2 小时） |
| 中长期记忆 | **MySQL（结构化数据）+ 向量库（语义检索）** |
| 事实和偏好 | **永久保存**（不过期） |
| 历史摘要 | **分层过期**（0-90 天热存储 → 90 天-1 年冷存储 → 1 年后删除） |
| 单一事实来源 | MySQL |

**表设计**：

```sql
CREATE TABLE user_memories (
    id VARCHAR(32) PRIMARY KEY,
    user_id VARCHAR(32) NOT NULL,
    memory_type ENUM('preference', 'fact', 'summary') NOT NULL,
    memory_key VARCHAR(100) NOT NULL,
    memory_value TEXT NOT NULL,
    embedding_id VARCHAR(32),
    confidence FLOAT DEFAULT 1.0,
    source ENUM('auto', 'manual') DEFAULT 'auto',
    is_archived BOOLEAN DEFAULT FALSE,
    created_at DATETIME NOT NULL,
    updated_at DATETIME NOT NULL,
    expires_at DATETIME,
    deleted_at DATETIME,
    INDEX idx_user_type (user_id, memory_type),
    INDEX idx_expires (expires_at),
    INDEX idx_archived (is_archived)
);
```

### 15.4 记忆管理与权限

| 维度 | 决策 |
|---|---|
| 用户权限 | **可查看 + 编辑 + 删除 + 导出 + 一键清空** |
| 入口 | "个人中心" → "我的记忆" 页面 |
| 导出格式 | JSON |

### 15.8 记忆流转机制

```
用户对话
   ↓
短期记忆（Redis，TTL 2 小时）
   ↓ LLM 自动检测 + 用户手动标记
提升为中长期记忆（MySQL + 向量库）
   ↓
事实/偏好：永久保存
历史摘要：90 天 → 冷存储 → 1 年删除
```

**自动提升触发条件**：

| 类型 | 触发条件 |
|---|---|
| 事实 | LLM 识别"我叫XX"、"我是XX部门" |
| 偏好 | 用户说"以后用XX"、"我习惯XX" |
| 摘要 | 对话超过 12K 触发压缩时 |

### 15.9 异步记忆抽取机制

| 维度 | 决策 |
|---|---|
| 触发时机 | **仅三种**：显式记住 + 会话空闲超时 + 滑动窗口容量触发 |
| 定期扫描 | **不做**；废止“每 30 分钟批量扫描活跃会话” |
| 抽取边界 | 只允许当前启用的 `memory_extract_fields.field_key`；白名单外结果丢弃 |
| 异步队列 | **Celery + RabbitMQ**（与 PRD 已定一致） |
| 抽取范围 | **事实 + 偏好 + 历史摘要**，但必须受白名单类别与字段限制 |
| 失败处理 | **重试 3 次后跳过**（不阻塞对话） |
| 去重策略 | **LLM 提取 + Embedding 去重**（相似度 > 0.9 跳过） |
| 来源标记 | **`auto_sliding_expired`**（便于审计） |

**异步流程**：

```
对话触发条件满足（显式记住 / 空闲超时 / 滑动窗口容量）
   ↓
Celery 异步任务（对话主路径只投递，不等待抽取）
   ↓
┌─────────────────────────────────────┐
│  LLM 按启用白名单分析本轮对话        │
│    ├─ 抽取允许的事实字段              │
│    ├─ 抽取允许的偏好字段              │
│    ├─ 生成允许的历史摘要字段          │
│    └─ 白名单外 memory_key 直接丢弃    │
└──────────────┬──────────────────────┘
               ↓
┌─────────────────────────────────────┐
│  Embedding 去重                       │
│    - 相似度 > 0.9 → 跳过             │
│    - 相似度 0.7-0.9 → 提示合并        │
│    - 相似度 < 0.7 → 视为新记忆        │
└──────────────┬──────────────────────┘
               ↓
┌─────────────────────────────────────┐
│  写入 MySQL + Milvus                 │
│    source = 'auto_sliding_expired'   │
└─────────────────────────────────────┘
```

**触发时机详细说明**：

| 时机 | 触发条件 | 优先级 |
|---|---|---|
| 显式记住 | 用户明确说“请记住”“以后请”等口令；本轮响应结束后立即异步投递 | 高 |
| 空闲超时 | 会话持续无新消息达到可配置空闲阈值（默认 3 分钟） | 中 |
| 滑动窗口 | 短期记忆达到容量阈值时异步投递，并使用防抖标记避免重复 | 中 |
| 定期扫描 | **不执行** | — |
