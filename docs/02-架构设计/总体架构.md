## 一、架构原则

| 原则 | 说明 |
|---|---|
| **模块化单体优先** | 初期不上微服务，按模块清晰拆分 |
| **异步化** | 重任务走队列，API 层永远轻量 |
| **无状态 API** | 所有状态外置到 Redis/MySQL/Milvus |
| **可演进** | 单体 → 模块化单体 → 微服务平滑演进；IM 通道未来可插拔 |
| **国产开源优先** | Milvus、FastAPI 等国产或国产化友好项目 |

## 二、分层架构

```
┌──────────────────────────────────────────────────────────┐
│                    接入层 (Access)                         │
│  Web 控制台（系统对话 · 交互卡片）  ·  OpenAPI  ·  CLI   │
│  （本阶段不做 OpenIM / 企业 IM）                           │
└──────────────────────┬───────────────────────────────────┘
                       ↓
┌──────────────────────────────────────────────────────────┐
│                  网关层 (Gateway)                          │
│  鉴权 · 限流 · 路由 · 审计日志（单租户）                   │
└──────────────────────┬───────────────────────────────────┘
                       ↓
┌──────────────────────────────────────────────────────────┐
│                   Agent 编排层                            │
│  Planner · Memory · Skills · call_agent · Skill Registry │
└──────────────────────┬───────────────────────────────────┘
                       ↓
┌───────────────────────────────────────────────────────────┐
│                    能力层 (Capabilities)                    │
│  LLM(LiteLLM) · RAG(Milvus Hybrid) · 工作流(Celery) · KG  │
└──────────────────────┬───────────────────────────────────┘
                       ↓
┌───────────────────────────────────────────────────────────┐
│                   基础设施层 (Infra)                       │
│  MySQL · Redis · RabbitMQ · Milvus · Neo4j · OSS          │
│  Langfuse（自托管）· Prometheus · Grafana · K8s            │
└───────────────────────────────────────────────────────────┘
```

## 四、关键数据流

### 4.1 智能问答数据流

```
用户登录 Web → 系统对话页发问
   ↓
API Gateway：Session 鉴权 / 限流 / 审计
   ↓
Agent 编排（可指定 Agent 或智能路由 + Web 澄清）
   - 技能 / RAG / call_agent（两层 FC）
   ↓
RAG / 技能工具 / LLM（经 LiteLLM，SSE 流式）
   ↓
输出审核 + citation（RAG 强制）
   ↓
流式响应 → Web 前端
   ↓
异步落库：对话 / Token / 反馈
```

### 4.2 工作流执行数据流

```
触发器（手动 / 定时 / 技能 workflow_call / API）
   ↓
Celery：写实例 dag_snapshot → 按 DAG 执行
   ↓
人工节点：waiting 落库释放 worker → Web /approvals 确认 → 续跑
通知节点：写 notifications + 可选 Webhook
   ↓
完成 / 失败 → 站内通知（不推中间进度）
```

### 4.3 文档入库数据流（v0.7.2：Web 上传）

```
用户在 Web（KB 页或对话附件）上传文件
   ↓
zeroAgent：写线上 OSS，落库文档草稿
   ↓
Celery：解析 → Chunk → Embedding → Milvus
   ↓
命中测试 → 通过后可发布
```

> 不依赖 OSS 桶事件；**不做** OpenIM file-callback。

## 七、安全架构

### 7.1 认证层级

```
用户 → Web 登录（自建账号 Session）→ API Gateway → 业务模块
                              ↓
                         API Key（开发者）
```

### 7.2 数据分级

| 级别 | 示例 | 处理 |
|---|---|---|
| **公开** | 公司新闻、公开制度 | 无限制 |
| **内部** | 部门规章、技术文档 | 同部门可访问 |
| **机密** | 薪资、合同 | 权限审批 + 审计 + 脱敏 |
| **绝密** | 战略规划 | 不入知识库 |

### 7.3 审计
- 对话 / 工具调用 / 配置变更留痕（留存见库表文档）

## 八、性能优化策略

| 优化点 | 方案 |
|---|---|
| **首字延迟** | SSE 流式 + 模型 TTFT 优化 |
| **检索加速** | Milvus 缓存热查询结果 |
| **数据库压力** | 读写分离 + 慢查询索引 |
| **重复问答** | Redis 缓存相同问题的答案 |
| **静态资源** | CDN + OSS |
| **长任务** | 异步队列；结果站内通知 |

## 九、技术债务管理

| 风险 | 缓解 |
|---|---|
| 单体膨胀 | 模块边界清晰 |
| 模型依赖 | 多 provider + fallback |
| 数据迁移 | 预留升级路径 |
| 未来 IM 接入 | 保留通道适配器抽象，业务不绑具体 IM |
